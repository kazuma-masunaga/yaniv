# ヤニブ（Yaniv）ブラウザ版

トランプゲーム「ヤニブ」を、素の HTML/CSS/JavaScript だけで遊べるアプリです。ビルド工程はなく、`index.html` / `engine.js` / `net.js` の 3 ファイルを静的ホスティング（GitHub Pages など）に置くだけで動きます。

## 遊び方（3 つのモード）

ロビーで入口を選びます。

| 入口 | 内容 |
| --- | --- |
| **この端末で遊ぶ** | 1 台の端末で、人間 1 人以上 + CPU を混ぜて 2〜8 人。人間が 2 人以上なら自動でパス＆プレイ（手番ごとに「端末を渡してください」の画面が出る）。 |
| **部屋を作る** | 名前を入れて「部屋を作る」。4 桁の数字の部屋コードと共有 URL が表示されるので、友だちに送ります。人数枠（2〜8）・ジョーカー・脱落ライン・CPU の強さを決め、参加者がそろったら「開始」。空席は CPU で埋まります。 |
| **部屋に参加** | 共有 URL を開く（コードが入力済みになる）か、部屋コードと名前を入れて「参加」。ログインは不要です。ホストが開始するまで待機画面でロビーをミラー表示します。 |

対局画面は 3 モード共通です。スマホ（幅 600px 以下）では部屋コード・ルール・相手の情報・ログ（最新 2 行）を詰めて表示し、iPhone の標準サイズならスクロールなしで 1 画面に収まります。相手が 5 人以上（合計 6〜8 人）のときは、相手の枠を 3 列のコンパクト表示（名前と「手札n・累計m」の 2 行、接続状態は色付きの丸）に切り替えます。オンライン時は自分の手番以外はボタンが無効になり、他プレイヤーに「接続中 / 切断中」のバッジが付きます。ラウンド結果・ゲーム終了画面で「次のラウンド」「もう一度」を押せるのはホストだけで、参加者には「ホストを待っています」と表示されます。

- **CPU の待ち時間**: CPU は手番の前に少し考える間を置きます（CPU 3 人以下 0.6〜0.9 秒）。CPU が多い卓では 1 周が長くなりすぎないよう、4 人 0.5〜0.75 秒 → 5 人 0.45〜0.65 秒 → 6 人以上 0.4〜0.6 秒と段階的に短くなります。
- **6〜8 人の卓**: 配られる手札が 30〜40 枚になるので山札がすぐ尽き、捨て札（一番上の組以外）を切り直して山札にする場面が多くなります。
- **スタンプ（オンラインのみ）**: 対局中、手札の上の「😊 スタンプ」から 8 種の絵文字（嬉しい・怒り・悲しい・ドヤ・やばい・考え中・ナイス・お願い）を送れます。相手のカードに吹き出しで 2.5 秒表示され、連打は 1.5 秒に 1 回まで。

### ルールの要点
- 各 5 枚配り、山札の 1 枚を捨て札にして開始。A=1、2〜10 はそのまま、J/Q/K=10、ジョーカー=0 点。
- 手番では「ヤニブ宣言（手札合計 7 点以下）」か「1 組捨てて 1 枚引く」。捨てられる組は 1 枚 / 同ランク 2 枚以上 / 同スートの連番 3 枚以上（ジョーカーは連番のワイルド）。
- 引くのは山札か、直前の人が捨てた組のカード（連番は両端のみ）。
- ヤニブ宣言で全員公開。宣言者より手札点が低い人がいれば「ヤニブ返し」（宣言者 +30 点、返した人 0 点）。同点は宣言者の勝ち。
- 累計が脱落ライン以上で脱落。最後の 1 人が勝ち。

## ホーム画面に追加（PWA）

スマホのブラウザで「ホーム画面に追加」すると、アプリのように全画面で起動します（ストア公開はしていません）。

- **Android（Chrome など）**: ロビーに「ホーム画面に追加」ボタンが出ます。出ないときはブラウザのメニューから追加。
- **iPhone / iPad（Safari）**: 共有ボタン → 「ホーム画面に追加」。
- 一度開けば、電波がなくても **「この端末で遊ぶ」** は動きます（Service Worker `sw.js` がページとスクリプトをキャッシュ）。オンライン対戦（部屋を作る／参加）はインターネット接続が必要です。
- 更新は network-first（ブラウザの HTTP キャッシュも通さず毎回サーバーに確認）なので、公開を更新すると次にオンラインで開いたときに反映されます（GitHub Pages の `max-age=600` の影響も受けません）。電波が弱く 3.5 秒応答が無いときはキャッシュで起動し、裏で更新を取り込みます。キャッシュ対象のファイルを増減したら `sw.js` の `VERSION` を上げてください。

## 部屋の仕組みと制約

- 通信は **PeerJS（WebRTC）による P2P** です。状態を持つのは **ホストだけ**（ホスト権限方式）。参加者は「手」をホストに送り、ホストが検証して進め、各参加者には「その人から見える状態」だけを配信します。他人の手札や山札の中身は参加者の端末に届きません。
- **ホストがタブを閉じると部屋は終了します。** ホスト画面には常にその注意が表示されます。参加者には「部屋は終了しました」と表示されます。
- 参加者側の接続が切れた場合は自動で再接続（2 秒 → 4 秒 → 8 秒 … 最大 30 秒間隔）を続け、同じ席に戻ります。席の情報は `localStorage` に保存されるので、ページを再読み込みした後にもう一度「参加」を押せば同じ席に戻れます。切断中の人の手番になったら、ホストは「CPU に交代」でその席を CPU に替えられます。
- **PeerJS の公開シグナリングサーバー（0.peerjs.com）に依存します。** 部屋コードの解決と接続の確立にだけ使い、ゲームのデータは端末同士で直接やり取りします。公開サーバーが混雑・停止していると部屋を作れない／参加できないことがあります。企業ネットワークなど WebRTC が通らない環境では接続できない場合があります（STUN のみ、TURN は未設定）。
- 部屋コードは **4 桁の数字**（`0000`〜`9999`、先頭の 0 も含む）。`crypto.getRandomValues` で生成します。参加画面では数字キーボードが出て、全角数字は半角に直します。以前の 6 文字コードの URL を開いた場合は入力欄が空になり「部屋コードは4桁の数字です」と表示されます。
- PeerJS 上の ID は `yaniv-kmz7-<部屋コード>`（4 桁だけだと公開サーバー上で他のアプリと衝突しやすいため、アプリ固有の接頭辞を付けています。`net.js` の `PEER_PREFIX`）。使用中のコードに当たったら別のコードで最大 8 回まで作り直します。
- 4 桁なので、知らない人が偶然コードを当てて待機中の部屋に入ってくることがあります。ホストのロビーで参加者ごとの「外す」を押すと退出させられます（ゲーム開始前のみ）。
- 参加画面のコード欄には共有 URL をそのまま貼り付けても構いません（`room=` の 4 桁を取り出します）。

## ローカルで開く

`file://` で直接開いても「この端末で遊ぶ」は動きますが、オンライン対戦（PeerJS の読み込みと `?room=` 付き URL）は HTTP 経由で開いてください。

```sh
cd yaniv
npx serve .          # または: python3 -m http.server 8080
# http://localhost:3000 （serve の場合）を開く
```

複数端末で試すには、同じ LAN 上の端末から `http://<このPCのIP>:3000` を開くか、GitHub Pages に公開して共有 URL を使ってください（WebRTC は `https` か `localhost` でないと動かないブラウザがあります）。

## 公開手順（GitHub Pages）

1. `index.html` / `engine.js` / `net.js` / `manifest.webmanifest` / `sw.js` / `icons/` をリポジトリに置く（`tests/` はあっても問題ありません）。
2. GitHub のリポジトリ設定 → Pages → Branch を `main`（ルート）にして保存。
3. 表示された URL（`https://<user>.github.io/<repo>/`）を開く。「部屋を作る」で出る共有 URL はこの URL を元に生成されます。

## 開発

```sh
node --test tests/     # engine.test.js + net.test.js（PeerJS 不要。インメモリトランスポートで通信層をテスト）
```

- `engine.js` … ゲームロジック。決定論的（乱数は引数で注入）、状態は plain object。
- `net.js` … 部屋・ホスト権限・再接続のロジックと、トランスポート抽象（PeerJS 実装 / テスト用インメモリ実装）。
- `index.html` … UI。`engine.js` を判定表示に、`net.js` を通信に使います。
